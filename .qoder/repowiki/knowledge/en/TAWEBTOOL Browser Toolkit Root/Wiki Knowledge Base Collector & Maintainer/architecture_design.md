Two-layer orchestration: Bash wrappers (`run_wiki_collect.sh`, `opencode_wiki_maintainer.sh`) handle environment bootstrap (`.env` sourcing, `/etc/profile`, opencode auth.json fallback), logging to `logs/`, optional Git commit+push of updated files, and optional `mail` delivery. They delegate the heavy lifting to Node ESM scripts (`wiki_collect.mjs`, `wiki_email_digest.mjs`).

- `wiki_collect.mjs` is the core collector: reads source definitions from `data/wiki_sources.json`, loads shared memory/policy from `data/wiki_memory.json`, then dispatches per-source collectors (`collectRss`, `collectPage`, `collectGithubRepo`, `collectSearch`) which all funnel through `classifyCandidateWithAi` — a local keyword pre-screen (`relevanceScore` against `taKeywords` + `weightedKeywords`) followed by an optional DeepSeek `/chat/completions` call returning `{include,score,confidence,category,tags}`. Accepted candidates are turned into Markdown via `buildContent` / `buildChineseSummary` / `buildArticleNotes`, optionally re-enriched in batch (`enrichEntriesWithAi` → `replaceMarkdownSection` on sections like '自动归纳'/'文章阐述'/'TA 视角'), merged with existing `data/ta_wiki_entries.json` via `mergeEntries` (dedup by id/sourceId/sourceTitle, stale pruning unless `WIKI_KEEP_STALE=1`), and written back.
- `wiki_email_digest.mjs` diffs `logs/ta_wiki_entries.before.json` vs current entries, extracts changed sections, and either asks DeepSeek for a plain-text Chinese mail digest or falls back to `fallbackDigest`; output goes to `logs/wiki_email_digest.last.md`.
- `opencode_wiki_maintainer.sh` adds a third stage: if `opencode` CLI is installed it runs an interactive review prompt over the repo and appends its note to the report; otherwise records status 127.
- `fetch_models.sh` is unrelated utility that downloads ONNX models into `./models`.

Dependency direction: shell → Node scripts → external HTTP APIs (DeepSeek chat completions, GitHub REST, Bing RSS); data flows one-way into `data/*.json` and `logs/*`.
