- **Entry Point Pattern**: Each tool is a self-contained HTML file in `tools_html/` that loads shared infrastructure (`menu.js`, `common.css`) and tool-specific assets.
- **Dynamic Tool Injection**: `js/local_workbench.js` acts as a router/dispatcher. It reads the `data-local-tool` attribute from the host `<div id="panel">` and dynamically injects the specific tool's UI and logic into the DOM, enabling a single-page-app-like experience within individual HTML files.
- **Shared Infrastructure**: `js/menu.js` provides a centralized navigation system with search capabilities and accordion-style categories, injected into every page via `.left_menu`. `css/common.css` defines the global layout (sidebar, top search, main panel) and theme.
- **Modular JS Architecture**: Tool logic is encapsulated in individual JS files (e.g., `chatgpt.js`, `hdr_editor.js`). Complex tools often expose an initialization function (e.g., `window.initChatgptTool`) which `local_workbench.js` calls after injecting the base UI structure.
- **Client-Side Processing**: Heavy lifting (image compression, AI inference, video cutting) is performed in the browser using Web APIs, WebAssembly (FFmpeg.wasm), or external CDN libraries (model-viewer, marked, DOMPurify), minimizing backend dependency.
